# Medical MVP technical specification

The medical MVP technical specification is the Benefit Plan Standard's technical specification for the medical MVP (minimum viable product) of the CMS Health Tech Ecosystem Real-Time Benefits workgroup. It is a draft for the workgroup, not a workgroup decision: version 0.3.2, dated October 21, 2026.

The medical MVP answers questions about plan design: what a plan covers and what the member pays, whether the cost changes with where the member goes, whether a service has a limit, and whether the plan covers an extra benefit such as hearing aids. CMS already publishes these answers for Medicare Advantage and Marketplace plans. The specification says which items a pledgee, an organization that committed to the workgroup to publish MVP data for its plans, makes available, and where each item is, both in the CMS files and in a Benefit Plan Standard document. It covers 2 programs:

| Program | CMS files | Year | Read by |
|---|---|---|---|
| Medicare Advantage | Plan Benefit Package (PBP) Benefits, release "PBP Benefits-2027" | Contract year 2027 | The Medicare Advantage importer, `scripts/from-pbp.js` (see [CMS Medicare Advantage PBP files](./medicare-advantage-pbp.md)) |
| Marketplace | The Plan Attributes PUF, the Benefits and Cost Sharing PUF and the Network PUF | Plan year 2026 | The Marketplace importer, `scripts/from-marketplace-puf.js` (see [CMS Marketplace public files](./marketplace-public-files.md)) |

Both importers write their documents in the Benefit Plan Standard schema 1.2.0, a draft that becomes final after 2 independent adopters implement and validate it.

## What a pledgee publishes

A pledgee publishes files, not an API, and there is no hosted service. For each plan it publishes the Benefit Plan Standard document, `<plan key>.json`, which is SHALL and which the importer that wrote it has checked against the Benefit Plan Standard schema 1.2.0 draft, and the SBC InsurancePlan Bundle that the Benefit Plan Standard converter (`scripts/to-insuranceplan.js`) makes from it, `<plan key>.bundle.json`, which is SHOULD until the SBC InsurancePlan profile publishes, because the profile is at ballot. The files of each CMS release sit in their own folder, `<root>/<release>/`, such as `PBP-Benefits-2027` or `marketplace-puf-2026-2026-10-05`, and each Medicare Advantage release folder also holds `service-areas.json`, which is SHALL, so that an app can find the plan key from the member's county. An index at the root, `<root>/index.json`, written by `scripts/publish-fhir.js --pledgee`, lists every document, newest release first, with its plan key, program, plan year, release and data date. Every document carries its plan year, its CMS release and the download dates of the CMS files, and quotes the CMS cells its values were read from; today the 1 exception is a Marketplace row that is not covered, which quotes no cell.

The full contract, field by field, is in [What a pledgee publishes](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/docs/specs/rtb-medical-mvp/README.md#what-a-pledgee-publishes) in the technical specification.
